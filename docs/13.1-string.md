# Step 13.1: owned strings

Code: `alloc/string.t` (`String`, written in T on top of `List<u8>`
from step 9.1 and `str` from step 13). Nothing in the checker or the
interpreter changed.

```rust
use alloc::string::String;

fn main(os: std::Os) -> Result<(), std::io::Error> with alloc {
    let mut out = os.stdout;
    let mut s = String::from("héllo");
    s.push(',');
    s.push_str(" wörld");
    let written = out.line(&s.as_str()); // expect: héllo, wörld
    let len = s.len();
    s.pop();
    s.push('d');
    let t = String::from("héllo, wörld");
    let same = s == t;
    s.free();
    t.free();
    written?;
    out.line(&len)?; // expect: 14
    out.line(&same)  // expect: true
}
```

A `String` is text of its own, on the heap, which grows as characters
(`push`) and strings (`push_str`) are put at its end. `as_str()` sees it
as a `&str`, so everything `str` can do (docs/13-strings.md) a string
can: `s.as_str().chars()`, `s.as_str().split_at(3)`. A program says `use
alloc::string::String;`.

## A list that keeps a promise

A `String` is a list of bytes:

```text
pub struct String { bytes: List<u8> }
```

and its *invariant* is the promise a `str` makes:

> The bytes of `bytes` are UTF-8.

`as_str` is the one `unsafe` block, and it's that promise:

```text
pub fn as_str(&self) -> &str {
    // SAFETY: its bytes are UTF-8, by the invariant.
    unsafe { str::from_utf8_unchecked(self.bytes.as_slice()) }
}
```

Every other method is safe code. That's new. A `List`'s blocks each
checked what they needed, or counted on code with blocks of its own; the
safe methods, as `truncate`, couldn't break its invariant, as nothing
safe can reach a `RawBuf`'s slots. A string's bytes are a `List<u8>`,
which safe code can change any way it likes: `self.bytes.push(0xFF)` is
safe, and breaks the invariant. So the block in `as_str` is right only if
`push`, `push_str`, `pop`, `truncate` and `from_utf8` are, though none of
them says `unsafe`.

That's how far an `unsafe` block's proof reaches: to everything that can
touch the state it counts on. Here that's the module, as `bytes` is
private: nothing outside `alloc::string` can name it. Each method keeps
the invariant:

- `new` and `with_capacity` make no bytes; nor does `clear` leave any.
- `push_str(s)` puts `s`'s bytes at the end. They're UTF-8, as a `str`'s
  are, and UTF-8 after UTF-8 is UTF-8.
- `push(c)` pushes a zero byte for each byte `c` takes in UTF-8, and then
  writes `c` over them, with `encode_utf8`. A zero byte is UTF-8 (it's
  `'\0'`), so the invariant holds all along, not only at the end.
- `pop` and `truncate` cut where a character starts, as `is_char_boundary`
  says, and UTF-8 cut there is UTF-8 on either side.
- `from_utf8(list)` checks the list's bytes first, with `str::from_utf8`.

As in step 9, the interpreter checks what `from_utf8_unchecked` is
promised, each time it runs: a bug in one of these, such as `truncate`
without its `is_char_boundary`, is reported the first time a test calls
`as_str` after it, as `unsafe code broke its obligation`.

## Cutting a string

`pop` takes the last character out, and `truncate(n)` throws away the
bytes from `n` on. Both cut only where a character starts. `truncate`
says whether it could: if no character starts at `n`, it leaves the
string as it is and gives `false`, as `split_at` on a `str` gives `None`,
rather than panic.

```rust
use alloc::string::String;

fn main(os: std::Os) -> Result<(), std::io::Error> with alloc {
    let mut out = os.stdout;
    let mut s = String::from("añb");
    let at_2 = s.truncate(2);
    let at_3 = s.truncate(3);
    let written = out.line(&s.as_str()); // expect: añ
    let last = s.pop();
    s.free();
    written?;
    out.line(&at_2)?; // expect: false
    out.line(&at_3)?; // expect: true
    match last {
        Option::Some(c) => out.line(&(c as u32)), // expect: 241
        Option::None => Result::Ok(()),
    }
}
```

## Bytes in and out

`String::from_utf8(list)` takes a `List<u8>`, and makes it a string if
its bytes are UTF-8, or gives it back if they're not, so a list is never
lost. `into_bytes` is the other way: it uses the string up, and gives its
list.

```rust
use alloc::list::List;
use alloc::string::String;

fn main(os: std::Os) -> Result<(), std::io::Error> with alloc {
    let mut out = os.stdout;
    let mut l: List<u8> = List::new();
    l.push(0x68);
    l.push(0xC3);
    match String::from_utf8(l) {
        Result::Ok(s) => s.free(),
        Result::Err(mut l) => {
            l.push(0xA9);
            match String::from_utf8(l) {
                Result::Ok(s) => {
                    let written = out.line(&s.as_str()); // expect: hé
                    s.into_bytes().free();
                    written?;
                },
                Result::Err(l) => l.free(),
            }
        },
    }
    Result::Ok(())
}
```

## What a string may do

Its field is private, so a program can't make one of bytes that aren't
UTF-8, nor change its bytes:

```rust,error
use alloc::list::List;
use alloc::string::String;

fn main() with {alloc, panic} {
    let mut l: List<u8> = List::new();
    l.push(0xFF);
    let s = String { bytes: l };
    s.free();
}
// error: field `bytes` of `String` is private to `alloc::string`
```

`as_bytes` lends them to be read, as a `&[u8]`, not a `&mut [u8]`. A
`&str` from `as_str` borrows the string, so it can't be pushed to, which
may move its bytes, nor freed, while the `&str` lives:

```rust,error
use alloc::string::String;

fn main() with alloc {
    let mut s = String::from("a");
    let r = s.as_str();
    s.push_str("bcdefgh");
    let _v = r;
    s.free();
}
// error: cannot borrow `s` as mutable while `s` is borrowed
```

And it isn't `Discard`: it's used up by `free`, or `into_bytes`.

## Comparing

`==` and `Ord` are as for the strings' `str`s: the same bytes, and bytes
in order, which orders the characters by their numbers. They're impls in
T, of one line each.

## Why it's sound

- **S1 (the invariant).** Whenever no method of `String` is running, its
  bytes are UTF-8. By induction on what a program does: only the methods
  of `alloc::string` can reach `bytes`, as it's private (docs/06d-modules.md),
  and each keeps it, as above. A method can't be seen half done: no
  borrow of the string escapes one before it returns, and a panic aborts
  the program, so nothing runs after one that could look.
- **The block.** `as_str` gives `from_utf8_unchecked` bytes that are UTF-8,
  by S1, so the `&str` keeps step 13's invariant.
- **Borrows.** The `&str` borrows the string, so while it lives the bytes
  can't change or move (steps 5 and 9.1), and it can't outlive the string.
- **Linearity.** A `String` holds a `List`, which isn't `Discard`, so
  neither is it, and its buffer is given back once, by `free` or by
  whoever gets its list from `into_bytes`.

## Design decisions worth noticing

- **Trusted: nothing new.** No intrinsic, and no rule of the checker: a
  type, a field and an invariant, over a `List` and a `str`.
- **One `unsafe` block, with safe code under its proof.** The block is in
  `as_str`; what it counts on is kept by safe methods. A bug in one would
  need no `unsafe` to write. That's what privacy is for.
- **Never half broken.** `push` writes zeros and then the character, not
  bytes that aren't UTF-8 yet, so the invariant holds at every step, not
  only between calls.
- **Cutting can fail, without a panic.** `truncate` says if it cut, and
  `pop` gives an `Option`, as `str`'s `split_at` and `get` do.
- **`String::from(s)`, not `s.to_string()`.** A function of `String`, which
  can become a `From` impl later, rather than a method of `str` that
  `alloc` would add to `core`'s type.

## Exercises

1. Write `fn repeat(s: &str, n: u64) -> String`. What effects does it
   have, and why?
2. Write `String::insert(&mut self, i: usize, c: char) -> bool`, which
   puts `c` before byte `i`, if a character starts there. Does it need an
   `unsafe` block? Which part of the invariant must it keep, and at
   which steps?
3. In `push`, push `0xFF` bytes instead of zeros before writing the
   character over them. Is it still right? Is the invariant still true
   all along? Does it matter, given that panics abort?
4. Take `is_char_boundary` out of `truncate`. Which test finds it, and
   what does it say? Why isn't it the checker that finds it?
5. Write `as_mut_bytes(&mut self) -> &mut [u8] with unsafe`. What's its
   `# Safety`? Why must it be `unsafe` though it has no `unsafe` block in
   it?
6. `from_utf8` gives the list back when its bytes aren't UTF-8. What would
   go wrong if it gave `Option<String>`?
