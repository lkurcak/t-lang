# Step 6e.1: higher-ranked closures, and `filter`

Code: `src/check.rs` (`Checker::lambda_inner`: a closure's signature),
`src/check/generics.rs` (`Lifetimes::ClosureParams`: what a lifetime left
out in a closure's parameters means), `src/check/closures.rs`
(`Checker::settle_result`: working out its result's lifetimes),
`src/borrowck.rs` (`decide_result`, which does that from the body,
`closure`: checking the body for every lifetime, and `closure_generality`:
saying what's wrong when it doesn't hold) and `core/iter.t`
(`Iterator::filter`).

```rust
fn main() {
    let id = |x: &int| x;
    let a = 1;
    let long = id(&a);
    {
        let b = 2;
        print(*id(&b)); // expect: 2
    }
    print(*long); // expect: 1

    for x in (0..10).filter(|x| *x % 4 == 0) {
        print(x);
    }
    // expect: 0
    // expect: 4
    // expect: 8
}
```

A function type is *higher-ranked* in its lifetimes: `fn(&int) -> &int`
takes a reference of any lifetime, which each call picks
(docs/05-ownership.md). A closure's type wasn't. `id` above was checked at
one lifetime, which had to fit both `&a` and `&b`, and couldn't, since `b`
dies first. Worse, a closure passed to an `F: Fn(&int) -> bool` was checked
against it, but its *type* forgot that, so it didn't meet the same bound on
an impl, and `filter`, whose impl has one, couldn't exist (docs/06e-core.md).
Now a closure's type can be generic over lifetimes, as a function type is.

## What it takes

A closure is generic over the lifetimes its parameters are, which comes
from one of two places:

- **A bound, when one is wanted.** In `(0..10).filter(|x| *x % 4 == 0)`, the
  bound `P: FnMut(&Self::Item) -> bool` says what `|x| ..` takes, so it's
  generic over what that bound is.
- **Its annotations.** A lifetime left out in a closure's parameter's type
  is one it's generic over, as in a function type, or a function's
  signature: `|x: &int|` takes a reference of any lifetime.

A parameter with no annotation, and no bound to say, has one lifetime,
worked out from how the closure's used, as before.

## What it gives

Where a bound says what a closure gives, that's what it gives. Otherwise
its body says, as a body says what a variable's lifetimes are: a lifetime
left out in a closure's result, written or not, is one to work out, as one
left out anywhere in a body is. Each is, at the end of the function it's in
(`Checker::settle_result`):

- the lifetime of the one parameter its body returns a reference from:
  `|x: &int| x`, or `|x: &int, _y: &int| -> &int { x }`, gives a reference
  as long-lived as `x`, whatever that is;
- or, if it returns only what it borrows from what it captured, a lifetime
  fixed where it's made: `|_x: &int| &n`, or `|_x: &int| -> &int { &n }`,
  gives one as long-lived as its borrow of `n`;
- or, if it returns nothing borrowed at all, as `|_x: &int| -> Option<&int>
  { Option::None }` doesn't, it's as for a function: the lifetime of the one
  parameter, if there's one.

What a body returns a reference from is what flows into its result: the
regions that must outlive the result's, by the constraints the borrow
checker gets from it (`borrowck::decide_result`). If two parameters' do,
the result would have to live as long as both, and a type can't say that:

```rust,error
fn main() {
    let max = |x: &int, y: &int| if *x > *y { x } else { y };
    let a = 1;
    print(*max(&a, &a));
}
// error: this closure's result could borrow from `x` or from `y`
```

A body that returns a parameter's reference, or what it captured, gives the
parameter's lifetime, and the borrow checker then finds `&n` doesn't live
that long (`err_soundness_closure_hr_return_capture.t`).

Working it out is a choice of signature, nothing more. The body is then
borrow-checked against the signature chosen, the same as one written out,
so a wrong choice could only reject a program, never let a wrong one
through. Two things make it need care:

- **When.** The checker asks what a closure implements before the borrow
  checker runs: a closure in a `Wrap<P>` whose impl needs `P: Fn(&int) ->
  &int` meets it only if its result has its argument's lifetime. So what a
  type with such a closure in it implements waits until the end of the
  function, as it already did for one whose captures aren't worked out
  (`Checker::has_unsettled_closure`). There, captures are worked out first,
  then how each call gets at what it calls, then the results, innermost
  closure first, as a body needs all of those, and an outer closure's body
  calls the inner ones.
- **Where it's written down.** A closure that captures has its signature in
  one place, its `ClosureDef`. One that doesn't is a function type, copied
  wherever inference put it, so each lifetime to work out is a region of
  its own, `Region::Result(closure, index)`, and what it turned out to be is
  recorded by that (`Checker::decided`) and put in wherever types leave the
  checker:
  `Checker::solution`, the obligations proven at the end, and what
  monomorphisation copies.

## Checking the body

`lambda_inner` gives a closure a function type, or a type of its own if it
captures (docs/06c-closures.md), with its signature's `bound`: the
lifetimes it's generic over, named `'^0`, `'^1` and so on in it, as in a
function type. The borrow checker then checks the body as a function of its
own (`borrowck::closure`), as before, but for each of those lifetimes makes
a *placeholder*: a universal region that's known to outlive nothing, and to
be outlived by nothing but `'static`, the same as a call of a higher-ranked
function type makes (`Regions::relate_fns`).

Two things must hold for that to be sound.

**(H1) Any lifetimes will do.** The body was checked knowing nothing of its
placeholders: not how they relate to each other, nor to anything outside.
Whatever lifetimes a call picks, nothing the body did relied on them being
otherwise, which is *parametricity* for regions, as for a generic function's
lifetime parameters. So `call_into` picks new ones at each call, and a
closure's type can be compared with a bound that's higher-ranked.

**(H2) Nothing of them gets out.** What the body needs of its other regions
goes up to the function it's in, as constraints on the closure's type
there. What it needs of a placeholder can't: the function it's in doesn't
know the lifetimes a call will pick. So any constraint on one is an error,
in the closure. Keeping a reference it's given, in what it captured, needs
the placeholder to outlive the capture:

```rust,error
fn main() {
    let a = 1;
    let mut keep = &a;
    let mut f = |x: &int| {
        keep = x;
    };
    {
        let b = 2;
        f(&b);
    }
    print(*keep);
}
// error: this closure stores a reference from `x` in `keep`
```

and a result with the argument's lifetime that's sometimes what it
captured needs the capture to outlive the placeholder, which could be
`'static`:

```rust,error
fn main() {
    let a = 1;
    let r;
    {
        let n = 2;
        let f = |x: &int| -> &int {
            if *x > 0 { x } else { &n }
        };
        r = f(&a);
    }
    print(*r);
}
// error: this closure's result has the lifetime of `x`, which each call picks
```

Each placeholder is also apart from the others: `|out: &mut &int, x: &int|
{ *out = x; }` needs `x`'s lifetime to outlive `out`'s, which a call needn't
give it (`err_soundness_closure_hr_two.t`).

A placeholder has no implied bounds: `&'^0 &'^1 int` doesn't let the body
assume `'^1: '^0`. Rust's do, and with function subtyping they've been a
soundness hole for years (rust-lang/rust#25860). Leaving them out is the
restriction that can be relaxed.

## Comparing types

**(H3)** Two signatures are the same type if they're the same up to the
names of the lifetimes they're generic over, and one that's generic over a
lifetime and one that isn't are different types. `|_x: &int| r`, which
returns `r` whatever it's given, is `fn(&'^0 int) -> &'r int`. It isn't an
`Fn(&int) -> &int`, which returns a reference as long-lived as its argument,
and an impl that needs that doesn't apply to it
(`err_soundness_closure_not_higher_ranked.t`). Comparing types with their
lifetimes erased would say otherwise, and let a reference outlive what it
points to.

Bound lifetimes are named in the order they're first written, both in a
bound and in a closure's annotations, so comparing names compares up to
renaming.

## `filter`

With that, `filter` is ordinary T, in `core/iter.t`:

```rust,fragment
let low = 3;
let above = |x: &int| *x > low;
print((0..10).filter(above).count());
```

Its impl is `impl<I: Iterator, P: FnMut(&I::Item) -> bool> Iterator for
Filter<I, P> where I::Item: Discard` (since step 7.1; it had a parameter
`T` for the values before, docs/07.1-impl-parameters.md). They must be
`Discard`: `next` throws away what `p` doesn't keep, so `filter` asks for
`Self::Item: Discard`, and an iterator of values that must be used up has no
`filter`. `p` gets each value by `&`, for as long as the call, so it can't
keep it, by (H2).

## Design decisions worth noticing

- **Parameters as in a signature, results as in a body.** What a closure
  takes, it says, as a function does, since its callers rely on it. What it
  gives, its body knows best, and a lifetime left out in a body is worked
  out: that holds for a closure's result too, written or not.
- **Inferred, then checked.** Working out a result's lifetimes only picks a
  signature, which the borrow checker then checks the body against. The
  inference can be as simple as it likes without being a soundness risk.
- **A bound wins.** Where a bound says what a closure takes and gives, its
  type is what the bound says: annotations can only agree.
- **Placeholders, not a new mechanism.** A closure generic over a lifetime
  is checked the way a call of a higher-ranked function type was: the
  borrow checker had what it needed.

## Deliberately missing (coming later)

| Missing | Why it's missing | Step |
|---|---|---|
| `for<'a> \|x: &'a int\| -> &'a int` | naming a closure's lifetimes; inference covers the common cases | — |
| a result that borrows from either of two parameters | needs "as long as both", an intersection of lifetimes | — |
| a use deciding a result the body leaves open | needs lifetimes unified in trait resolution; the function rule decides instead | — |
| `let f = \|x\| x` called at two lifetimes | generalising an inferred parameter's lifetimes, as `let` does in Hindley–Milner | — |
| implied bounds from a closure's parameters | unsound with function subtyping in Rust; strictness can be relaxed | — |
| `filter` on values that must be used up | something must use up what it doesn't keep | — |
| impls with `where` clauses | `Filter`'s extra `T` stands in for one | — |

## Exercises

1. Why does `|x| x` (no annotation) take only one lifetime, where `|x:
   &int| x` takes any? What would it take to make the first general too,
   and which closures would that reject?
2. Write a closure that needs implied bounds to check, and say how you'd
   rewrite it without them.
3. In `borrowck::decide`, make a result whose body returns nothing borrowed
   get a fixed lifetime instead of the parameter's. Which test fails, and
   is anything unsound?
4. In `borrowck::closure_body`, make the closure's bound lifetimes new
   region variables instead of placeholders. Which test catches it, and how?

   `Iterator::take_while` and say how many its type needs, and why.
