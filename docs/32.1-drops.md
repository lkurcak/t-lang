# Step 32.1: drops worked out before running

Code: `borrowck/drops.rs` (drop elaboration), `mir.rs` (`StmtKind::Drop`,
`StmtKind::Free`), `mono/glue.rs` (drop and `==` glue), `mono.rs`
(`Cx::body`: drops at the copy's types, `==` as calls, the closure-call
shim, `tidy`), `interp.rs` (`Interp::drop`, `left_behind`), `core/array.t`
(`from_fn`).

After step 32 the interpreter ran the borrow checker's MIR, but it still
worked out *what to drop* as it ran. At `dead _3` it looked in `_3`'s
slot and dropped whatever was left there: all of it, the part that wasn't
moved out, or nothing. A compiled program can't look: a slot is just
bytes. So this step works out, before the program runs, what each
`dead`, assignment and pattern drops, and writes it into the MIR.

```rust
use alloc::boxed::Box;

#[derive(Discard)]
struct Two { a: Box<i64>, b: i64 }

fn sink(t: Two) -> i64 { t.b }

fn pick(c: bool) -> i64 with alloc {
    let t = Two { a: Box::new(1), b: 2 };
    let mut n = 0;
    if c {
        n = sink(t);
    }
    n
}

fn main(os: std::Os) -> Result<(), std::io::Error> with alloc {
    let mut out = os.stdout;
    out.line(&pick(true))?;  // expect: 2
    out.line(&pick(false))?; // expect: 0
    Result::Ok(())
}
```

When `c` is true, `t` has been moved into `sink` by the time it goes out
of scope, and there's nothing to drop. When it's false, `t` is still
there, and its box has to be freed. `t mono` shows how that's decided:

```text
    bb0: {
        _14 = false;
        ...
        _2 = move _3;
        _14 = true;
        ...
        if copy _10 { bb1 } else { bb2 };
    }
    bb1: {
        _13 = move _2;
        _14 = false;
        _12 = sink(move _13);
        ...
    }
    ...
    bb3: {
        ...
        if copy _14 { bb4 } else { bb5 };
    }
    bb4: {
        drop _2;
        goto bb5;
    }
    bb5: {
        dead _2;
        ...
```

`_14` is a *drop flag*: set where `t` gets its value, cleared where it's
moved out, and read where it goes out of scope. `drop _2` drops all of
`t`, by its type's *drop glue*, a function monomorphisation writes:

```text
glue {drop}::<Two> {
    let _0: ();
    let mut _1: Two;
    bb0: {
        _0 = ();
        drop _1.0;
        dead _1;
        return;
    }
}
```

`b` is an `i64`, so dropping it does nothing, and there's no drop of it.

## Drop elaboration

It's rustc's algorithm, run on each body once the borrow checker has
checked it, at the body's own generic types:

- **Move paths.** The places the body owns that something moves out of,
  gives a value to, or takes apart, and the places they're in: locals,
  fields, variants' fields, an array's values, what a box points to.
  Never what's behind a reference: the body doesn't own that.
- **Dataflow.** Forward through the graph, which move paths *may* hold a
  value and which *may not*, at each point. Where paths meet, either.
- **Drops.** At each `dead`, assignment over an owned place, and
  `consume` (a pattern taking a value apart):
  - what's definitely there is dropped whole, `drop p`;
  - what's definitely not isn't dropped at all;
  - what may or may not be there gets a flag, and its drop happens only if
    the flag says so;
  - what's partly moved out is dropped *open*: what's left, part by part,
    in the order the fields are declared. An enum's parts are those of the
    variant it is, found by a `match`. A box's are what it points to, and
    then `free` frees the box itself. A type with a `discard` of its own
    has it called only if all of the value is there (each flag inside it
    says so), as before: taken apart, nothing calls it. In a type's own
    `discard`, `self` is always dropped part by part.
- A place whose type is `Copy` is never dropped: no copy of the body can
  have anything there to drop. An assignment drops the old value right
  before it, after the moves its right side makes (`x = x` drops nothing).
  An assignment of a call's result to a place that may hold a value gets
  a temporary in between, so the call's effects come before the drop, as
  they did.

Monomorphisation then keeps a `drop` only where dropping does something at
the copy's types: frees memory, calls a `discard`, or throws away what
isn't `Discard`, which the interpreter would report as a leak. What was
there only for the drops it left out goes too: a branch on a flag to a
block that does nothing, and the flags nothing reads.

## Glue

Glue is MIR that monomorphisation writes for what the program doesn't
spell out:

- `{drop}::<T>(x: T)`: `T`'s own `discard`, or each part that needs
  dropping, in order. Dropping an `Arena<T>` is the one left to the
  interpreter, as its values are only known as it runs; each is dropped by
  the glue of its box.
- `{eq}::<T>(a: &T, b: &T) -> bool`: `T`'s own `eq`, or field by field,
  stopping at the first that differs; the variants first, for an enum;
  through references and boxes; value by value for arrays, and for slices
  and strings by a loop over `len` and `index`.

`a == b` of anything but numbers, `bool`s, characters and `()` becomes a
call of what compares it, on references to `a` and `b`, as `a < b`
already became `Ord::lt(&a, &b)`. `Discard::discard` and `Eq::eq` used as
function values, for types whose impls are built in or derived, are the
glue functions.

Two other places dropped values behind the scenes, and no longer do:

- `array::from_fn(f)` was an intrinsic that called `f` and then dropped
  it. Now it's T code: it calls an intrinsic that borrows `f`, and drops
  `f` itself, as any function drops its parameter.
- Calling a closure by value whose body takes it by reference (a `Fn`
  closure passed where `FnOnce` was asked for) put it in a temporary,
  called it, and dropped it, inside the interpreter. Now monomorphisation
  writes that out: a temporary, a reference to it, the call, a `drop`.

## Why it's sound

- **E1, flags are exact.** A move path's flag is `true` exactly when its
  value is all there, but for what's moved out of the move paths inside
  it: it's set where the path, or what it's in, gets a value, and cleared
  where it, or what it's in, is moved out, goes out of scope, or is taken
  apart. So the elaborated drops drop exactly what was there, which is
  exactly what the interpreter dropped when it looked.
- **E2, same order.** An open drop goes through the parts in the order the
  interpreter's did, fields in declaration order, and a `discard` of a
  type's own is called exactly when the value wasn't taken apart.
- **E3, same in every copy.** Move paths and flags depend only on what's
  moved, which the borrow checker decided once, on the generic body (S3
  of docs/32-mir.md). Monomorphisation only leaves out drops that do
  nothing at its types.
- **E4, glue does what the interpreter did.** Drop glue and `==` glue do
  what the interpreter's `drop` and `==` did, part by part, in the same
  order.
- **E5, the borrow checker isn't affected.** Elaboration runs after it, on
  the copy that's kept for running, and drops stay where the `dead`s and
  assignments were, which `drop_uses` already treated as uses.

None of that needs taking on trust. The interpreter still keeps what's in
each slot, and checks it as it runs: a `drop` of a value that isn't all
there (a flag said yes when it should have said no), or a `dead`,
assignment or pattern leaving behind something that needed dropping (a
flag said no when it should have said yes, or an open drop missed a
part), is reported as an elaboration bug. What used to be the meaning of
dropping is now its test, on every program the tests run.

## Design decisions worth noticing

- **On the generic body, once.** Elaborating each copy could use its
  types to skip flags, but would make the decision once per copy, after
  the borrow checker, where a mistake in one copy would hide in the
  others. One decision, at the generic types, is the one the borrow
  checker's moves already made.
- **`drop` as a statement, not a terminator.** rustc ends a block at each
  drop, for unwinding. A T panic aborts, and calls are already rvalues
  here, so a drop is just a statement.
- **Glue in MIR, not in the interpreter or a runtime.** Everything that
  runs is MIR, which the C backend will translate. The interpreter's
  primitives are now `==` on scalars, `free`, and dropping an arena.

## Deliberately missing (coming later)

- A C backend translating this MIR (step 33).
- Optimising flags away: a flag that's always the same where it's read
  could be a constant. C compilers do that well enough for now.
- `#[derive(Eq)]` as T code rather than glue (a language change, for its
  own step).
